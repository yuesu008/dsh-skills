# 高难度 Rubrics 设计

**一句话原则**：Rubrics 的唯一验收标准是——两个独立评分者只看答卷和题目允许的材料，会对同一条给出同一判定，并且强答卷与弱答卷的失分位置不同。做不到这两点，条数再多、写得再细也没有价值。

## 适用与不适用

适用：为人工评分或 LLM-as-judge 设计考点；改写和加严已有 Rubrics；审查评分标准是否存在无法判分、重复扣分、可被套话蒙混的条目；把一道题拆成可分的判断节点。

不适用：直接解题或给参考答案；能用单元测试、断言脚本判定的事（直接写测试）；题干本身就缺判分所需信息且无法冻结假设（先改题，再写 Rubrics）；要求评估"文风好不好"但没有可观察判据的场合。

## 工作流（顺序固定，不跳步）

0. **判请求类型**：新建 Rubrics / 改写加严 / 只做审查 / 生成评分提示词。只做审查时不擅自重写题干或生成新题；只要求 Rubrics 时不擅自改题干、加资料、扩任务。
1. **建任务模型**：读题干、数据、附件与限制，明确目标结论、可用证据、必要计算、交付形式、禁止引入的外部资料。读不到的材料不能假装读过；由此产生的缺口写成"冻结假设"，不写成"标准答案"。
2. **冻结判分口径**：定判分模式（二元／分级／加权）、门槛与否决项、同根因扣分规则、容差来源。口径未定就写条目，后面必然出现同一条两种合理答案。
3. **列判断节点 → 写条目**：按解题链列节点，再按 [R2](#硬规则) 原子化，按模块连续编号。
4. **验证**：反例穿刺、等价解穿透、冗余删除，三项见 `references/scoring.md`。没做就标"未验证"，不宣称已验证。
5. **交付**：用下方输出契约，逐项过自检清单。

## 硬规则

**R1 口径先冻结。** 计算前锁定版本、时间窗、样本集合、单位、分母、归一化基准、统计方法、有效位数、是否允许外推。后续沿用；改变时给原因与影响。只冻结与本题有关的口径。

**R2 一条一个失败模式。** 条目内若有两个要求能分别判真伪（删掉一个，剩下的仍可判通过／失败），就拆成两条。只有多个要求是同一结论的必要条件（缺一则该结论不成立）时才允许合取，并在条目里写明"全部成立才算通过"。同类判定的多个实例（如四个数值的绑定）可以合并，不同能力不可合并。判据与拆条示例见 `references/item-patterns.md`。

**R3 可判性。** 评分者只凭答卷与题目允许的材料判定；每条至少一个可核对锚点（数值、单位、位置、条件、判定规则）。禁止把"运行代码""复现实验""查阅未提供的资料"写成通过条件，除非评测流程明确提供该步骤。允许"资料不足，无法确定"在正确识别缺失并限定结论时成为合格答案。

**R4 数值给容差与来源。** 写公式或可接受等价方法、单位、关键中间量、结果与容差，并交代容差怎么来的。区分绝对／相对误差，接近零不用相对误差；精确离散结果不设容差；科学等价的路径与表述都接受，不把参考答案措辞当唯一答案。

**R5 覆盖七类节点。** 任务解析与口径、证据定位、多步计算、独立复核、异常分支、边界条件、结论与适用范围。按题目实际需要分配，不为凑覆盖编造任务；正常分支也必须可判。

（R5 续）考察题目字面未要求的节点（独立复核、分布与置信区间、未提及的对照）时，在该条末尾加标注"（超出题面要求，用于区分能力强弱）"，并在判分口径里说明这些条不计入"按题面完整作答"的基础判定——否则一份题面全对、表述克制的答卷会被判失分，评分者也没法解释。

**R6 数量按判断节点。** 以独立判断节点数为准，复杂题默认 40 条上下（10–50 区间）；超量时合并同类失败模式的实例，不合并不同能力；不足时先查是否漏了冲突裁决、异常分支与判定边界，仍不足就如实调整数量。

**R7 不泄题。** Rubrics 若会随题展示给被测模型，条目不得写出待求结论、关键中间值、修复方案或"应当选 X"。评分者版与被测者版分开交付。

**R8 不虚报。** 未做反例穿刺就写"未验证"；不宣称已验证区分度、信度或与人工评分一致。存在不确定的预期值时标注待核实，不发布伪确定标准。

## 输出契约

```markdown
# Rubrics：<题目简称>

## 判分口径
- 判分模式：二元通过／不通过（默认）｜分级 0/1/2｜加权（说明权重依据）
- 门槛与否决项：<没有就写"无">
- 同根因规则：<上游错误如何沿袭，最多几跳>
- 数量：N 条

## 材料缺口与冻结假设
<每条一句话：缺什么、按什么假设判、不影响什么>

## 一、<模块名>（1–k）
1. 模型是否……
2. 模型是否……

## 附录 A 参考值与容差（评分者，非考点）
## 附录 B 反例穿刺记录（未做写"未执行"）
```

模块名按解题链取（口径解析／证据定位／计算链／独立复核／异常与边界／结论收束／修复正确性／论证完备性），不按"难度等级"取名。附录不编号，避免被当成考点。

## 交付前自检（逐项打勾，二选一，不许"基本满足"）

1. 序号 1..N 连续无重复，条数与声明一致，模块区间与条目对得上。
2. 每条以"模型是否"起句，落脚在一个可判真伪的判定上，不是"分析……""考虑……"。
3. 抽查 5 条做删除测试：删掉其中任一要求后剩下的仍可独立判定 → 该条需拆分。
4. 空泛词零命中：充分、合理、深入、准确、全面、恰当、良好、到位、严谨、清晰（"清晰"仅可用于有格式判据处）。
5. 每条至少一个锚点：数值、单位、位置（页／节／表／图／行号）、条件或判定规则。
6. 数值条有容差与来源；精确离散值未设容差；未把相对误差用在近零量上。
7. 每条都能说出"什么样的答卷会失分"，或由前置条件唯一推出。
8. 异常与边界条写清"触发时怎么判、未触发时怎么判"。
9. 结论条只收束前文已判过的证据，不引入新论断。
10. 拿一份"复述材料+只报终值"的弱答卷过一遍：关键节点确实失分。
11. 材料缺口已写成冻结假设，未编造数值、页码、实验条件或"标准答案"。
12. 若用户要分值：档位边界只由单一变量决定，权重只落在关键判断节点，无同一根因无上限重复扣分。
13. 问一句"一份题面全对但表述克制的答卷会不会失分"：会，就检查该条是否考察了题面未要求的内容；是则按 R5 末尾加"超出题面要求"标注并在判分口径中声明不计入基础判定，否则删条或改题。

## 常见失败形态

| 现象 | 后果 | 改法 |
|---|---|---|
| 一条里塞 3–4 个要求，全对才给分 | 强答卷因一处笔误整条归零，区分度反向 | 拆条或明确合取，见 R2 |
| 条目以"分析是否深入／结论是否合理"收尾 | 评分者只能凭印象，双人判分不一致 | 换成可观察行为 + 阈值 |
| 异常分支只写"处理异常" | 异常未出现时无法判 | 写"触发时做 A，未触发时判 B" |
| 同一根因在 5 条里各扣一次 | 一处错导致总分崩塌 | 定义沿袭规则，见 `references/scoring.md` |
| 只奖终值不奖过程 | 蒙对与算对同分 | 对影响后续结论的中间量单列 |
| 口径未冻结就要求比较 | 两种答案都合理，却只有一种得分 | 先冻结再比较，见 R1 |
| 条目要求"可运行""已复现" | 评分者无法验证，条文空转 | 换为可静态核对的判据，或明确评测含执行 |
| 为凑 40 条扩无关知识题 | 篇幅膨胀，区分度不变 | 合并同类实例，或如实减量 |
