# high-difficulty-rubrics

为大模型能力评测设计**可客观判分**的高难度 Rubrics（评分标准／评分细则／判分点／LLM-as-judge 评分提示词）。

核心验收标准只有两条：两个独立评分者只看答卷和题目允许的材料，会对同一条给出同一判定；强答卷与弱答卷的失分位置不同。条数多、写得细都不算达标。

## 解决什么问题

- 题目本身有难度（多步计算、多源数据冲突、材料缺口、代码缺陷定位、长文论证），但写出来的考点是"分析是否深入""结论是否合理"这类无法判分的条目。
- 一条考点里塞了四五个要求，强答卷因一处笔误整条归零，区分度反向。
- 没有判分口径：容差从哪来、上游算错下游还要不要扣、异常分支未触发时怎么判，全靠评分者临场发挥。
- 写完没有验证，无法说明"这套标准真的能分开强弱答卷"。

## 目录结构

```
high-difficulty-rubrics/
├── SKILL.md                     # 主流程：工作流 5 步、硬规则 R1–R8、输出契约、13 项自检、失败形态表
├── references/
│   ├── item-patterns.md         # 原子化三测试、五类句式骨架、容差与等价解、复合拆条前后对照、反模式改写表、完整小样例
│   ├── scoring.md               # 判分模式、聚合与门槛、否决项、同根因沿袭、阈值校准、反例穿刺、等价解穿透、区分度矩阵
│   └── domain-checks.md         # 半导体、材料数据审查、科研测评、代码与 agent 任务、通用问答与长文的领域口径检查

```

安装后在 DSH 中由 `description` 自动路由；也可以显式调用本技能。

## 使用方式

提供题干（可附数据、图表、代码、文档），说明用途（人工评分 / LLM-as-judge / 只要审查不重写）。技能会按输出契约返回：

1. 判分口径（模式、门槛、同根因规则、条数）
2. 材料缺口与冻结假设
3. 按解题链分模块的 N 条考点（默认二元通过/不通过）
4. 附录 A 参考值与容差、附录 B 反例穿刺记录

要求只做审查时，只输出问题条目与改法，不重写题干、不生成新题。

## 设计要点（为什么这样写）

- **原子化优先**：一条一个失败模式，靠删除测试／半对测试／换位测试判定，而不是靠语感。这是旧版最大的缺口——实测三份真实题目时，17/43、13/48 条塞了 4 个以上可分别判真的要求。
- **口径先冻结**：版本、集合、单位、分母、有效位数、统计方法、能否外推，先定再判，否则同一条会有两种"合理"答案。
- **可判性硬约束**：不允许把"运行代码""复现实验""查阅未提供资料"写成通过条件。
- **不虚报**：没做反例穿刺就写"未执行"，不宣称已验证区分度或信度。
- **不泄题**：Rubrics 若随题展示，条目不得写出待求结论或关键中间值；评分者版与被测者版分开。

## 打包与上架

见仓库根目录说明或 `SKILL.md` 所在目录的打包步骤。要求：

- 顶层目录名必须与 frontmatter 的 `name` 完全一致（`install.ts` 会校验，不一致报 `downloaded skill declares name X, expected Y`）。
- frontmatter 只使用 DSH 支持的字段：`name`、`description`、`whenToUse`、`disable-model-invocation`、`user-invocable`（kebab-case；`disableModelInvocation` 之类的 camelCase 会报错）。
- 压缩包内需包含 `SKILL.md` 于 `<skill-name>/SKILL.md` 位置。

## 实测（同一道题，新旧版本对比）

同一题干（SiC MOSFET 比导通电阻多源比对）分别用 v1 与 v2 生成，机械指标：

| 指标 | v1 | v2 |
|---|---|---|
| 条数 | 43 | 40 |
| 平均条目长度 | 101.9 字 | 48.3 字 |
| 平均子句数 | 3.98 | 2.30 |
| ≥5 子句的复合条 | 18 条（41.9%） | 0 条 |
| 最长条目 | 189 字 | 79 字 |
| 输出契约符合度 | 章节结构自定 | 与契约逐节对应 |
| 反例穿刺／等价解穿透 | 未执行 | 5 份反例 + 1 份等价解，改条 5 条 |

v2 的验证记录显示：等价解穿透抓出 2 处误杀（一条强制要求绝对差、一条要求两条路径互检），反例穿刺抓出 1 处预期清单错误（条目本身无洞），都回改到条目里——这是 v1 完全没有的步骤。
- v1：初始版本，覆盖口径冻结、证据定位、多步计算、交叉复核、异常分支、边界条件、结论收束。
